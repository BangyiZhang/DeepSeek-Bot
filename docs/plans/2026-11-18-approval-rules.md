# 审批：「总是允许」规则和超时自动拒绝

- 日期：2026-11-18
- 状态：第一轮（只在 fork 里）
- 相关：[Bot 托管任务里的提问](2026-10-28-durable-user-questions.md)

## 为什么

Bot 在 `workspace-write` 权限下，要写工作文件夹外面的文件（比如 `~/.agents/skills` 里的技能）或者跑一条要更宽沙箱的命令时，DSH 会弹审批。DSH 的审批只有「允许一次」和「拒绝」，没有超时：用户不答，这一轮就一直停着，Bot 自己的聊天里后面的消息排在它后面，群里这个成员也一直卡着。用户常常不知道它在等，或者每次都要点同一个「允许」。

## 做法

两件事，都在 DS Bot 插件里做，不改 DSH：DS Bot 本来就排在 DSH 自己的应答前面接每一个 Bot 的 `approval/request`（`src/host/approvals.js`）。

### 1. 「总是允许」规则（每个 Bot 自己的）

- 审批卡上多一个按钮「总是允许」。点了就给这个 Bot 存一条规则，并且这一次也允许。
- 规则只有两种，范围由 DS Bot 从这次调用的参数算出来，卡上写清楚：
  - **文件夹**：`write` / `edit` / `str_replace_editor` 的路径，`apply_patch` 里每个 `*** Add/Update/Delete File:` 和 `*** Move to:` 的路径。规则是这些路径所在的文件夹（多个路径取共同的上级）。以后这个 Bot 的文件工具申请，**每个路径都在这个文件夹里**才自动允许。路径先按会话工作目录解析成绝对路径，再取最近一个存在的上级的真实路径（`realpath`），防符号链接绕出去。
  - **命令**：`bash` / `pwsh` 的命令。规则是**完全相同的这条命令**，不做前缀或通配匹配。
- 别的工具发来的审批（没有路径也没有命令）不给「总是允许」，照旧问。
- 规则存在 Bot 上（`bot.approvalRules`），只有用户能加（审批卡、手机和 IM 的应答都走用户的接口），Bot 的工具不能加。在 Bot 详情的「权限」下面列出来，可以一条条删掉。
- 自动允许的那一次照样走 DSH 的审批记录，结果是 `allowed-once`，只对那一次调用生效，和用户手点一样。

### 2. 超时自动拒绝

- 团队设置：「没人回答的审批，N 分钟后自动拒绝」。默认 10 分钟，可选 5 / 10 / 30 / 60 分钟或关闭（`prefs.approvalTimeout`，单位分钟，0 = 关）。
- 到时间 DS Bot 替用户答「拒绝」：Bot 收到被拒，接着干别的；DSH 自己的卡收回。卡上和群里能看到「无人回答，已自动拒绝」。
- 只是拒绝，从不自动允许（和托管任务那份设计里「从不自动批准」一致）。
- 设成关闭就和以前一样，一直等。

### 界面

- 群里和托管任务的审批卡（DS Bot 自己画的）：三个按钮「拒绝」「允许一次」「总是允许…」，下面一行写剩下多久自动拒绝。
- Bot 自己的聊天里审批卡是 DSH 画的。DSH 等审批时会把输入框上方那一栏整个藏起来，所以提示条放进 DSH 卡里给的槽 `conversation.approval.detail`：这个槽是单个的，DSH 的聊天已经在里面画了命令，DS Bot 用更低的优先级接过来，先画 DSH 原来的那一块，再画自己的提示条（「总是允许」按钮和倒计时），做法和会话顶栏一样（`header-navigation.js`）。点了等于允许，DSH 卡随之收回。
- 超时自动拒绝以后 DSH 卡没了，输入框上方出现一行说明：没人回答，已自动拒绝，Bot 跳过这一步继续了。
- 手机 App 暂不加「总是允许」；超时在主机上算，手机上也生效。

## 不做的

- 不做通配或正则的命令规则：一条 `rm` 前缀规则就等于全权限。
- 不做团队共享的规则：权限是每个 Bot 自己的。
- 不改 DSH 的审批结果词汇（只有 `allowed-once` / `rejected` / `cancelled`）。
