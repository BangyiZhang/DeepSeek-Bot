# Durable task activity history

Questions are persistent task facts, not temporary dock state. The answering dock stays actionable only while a question is open. The task card and Settings provide the same read-only history: original question, detail, offered options, saved answer, timestamps and stage. Answering, completing, cancelling, reloading or restarting never removes that history. Existing saved questions are projected too; missing historical timestamps or lifecycle events are not fabricated.

Pi's own Jobs document records task creation, step admission, observed tool names, saved step completion, pause request versus actual checkpoint pause, resume request, answer continuation, cancellation request versus confirmed cancellation, and terminal review/completion. State-transition events are written in the same transaction as the checkpoint they describe. Tool names come from DSH's public execution history and are deduplicated by the saved per-session sequence, including after restart; their time is when first observed. No per-poll events, tool arguments, hidden prompts or chain-of-thought are recorded. A submitted step is not presented as proof that its tools ran. Partial cancellation output is not a completed step.

Lifecycle events retain the most recent 256 entries with an explicit truncation notice. The existing bounded question ledger stays separate and is never trimmed by event retention. Read-only projection removes runtime gate/call/session identifiers and applies the existing secret redactor. List polling carries only a history revision; expanded Settings entries load the selected task history lazily. Conversation cards already request a single task and receive history with their status.

Activity is a quiet expandable list using existing theme colors and controls. The recent-entry window keeps the latest question visible even when many tool calls follow; earlier entries remain accessible. Questions retain full text and answers, and original options can be expanded. Saved stage results and interruption evidence are available in the conversation as well as Settings. The list has no controls that can submit an old answer or restart execution. Ordinary questions and permission boundaries keep their existing semantics.

Verify real Pi close/reopen, multiple questions and immutable answers, cancellation with unanswered questions, pause/resume deduplication, partial cancellation output, API redaction/legacy records, and both UI themes with long content and a narrow column. No real user profile or credentials are test inputs. Packaging is out of scope for this source change.
